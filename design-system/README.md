# Design system

Onrace's design system in one folder, with one file the product links (Lesson 9, step 1, 2026-11-03). Until then `tokens/` and `components/` sat at the repo root and every page linked the two files in turn; the move changed no pixel (`concept/concept.md` → Lesson 9, step 1).

## The entry point

```html
<link rel="stylesheet" href="../design-system/index.css">      <!-- every token, then every component: one file -->
<script src="../design-system/tokens/theme.js"></script>          <!-- ?theme=light, the stress test (tokens/README.md) -->
<!-- Race browse and the showcase only, not render-blocking: -->
<link rel="preload" as="style" href="../design-system/map-data.css" onload="this.onload=null;this.rel='stylesheet'">
```

- **`index.css` is generated:** `scripts/build_components.py` writes it from `tokens/tokens.css`, then `components/index.css`, in that order. That is the order the two `<link>`s had, so the cascade is the same. It's one bundle, not an `@import` chain, so a page makes one request.
- **Never edit it.** Edit a source file, then run `python3 scripts/concept/build_stand.py`. The build runs `build_components.py` after it writes the contrast comment into `tokens.css`, so the entry point always carries the latest tokens.
- **The build stamps it** with `?v=<hash>` on every page that links it, and mirrors it, `map-data.css` and `tokens/theme.js` to `public/design-system/`.
- **`scripts/check_kit.py` enforces it.** It fails if a screen, the showcase or the shell doesn't link `design-system/index.css` exactly once, or links `tokens.css` or a components file directly.

## What's here

| Path | What it is | Edited by hand? |
|---|---|---|
| `index.css` | The entry point: tokens + components, one file | No, generated |
| `tokens/tokens.css` | Every value, on two levels: primitives (colors named by hue and L*), then the semantic color roles. Also the Dynamic Type, reduced-motion and Reduce Transparency overrides, and the light block | Yes. The contrast comment at the end is generated |
| `tokens/theme.js` | Turns `?theme=light` into `<html data-theme="light">` and keeps it for the tab | Yes |
| `tokens/tokens-audit.md` | Lesson 8's audit and record, step by step | Yes |
| `tokens/README.md` | The two levels and the theme test | Yes |
| `components/*.css` | One file per component, in order blocks (`components/README.md`) | Yes |
| `components/index.css` | The components bundled in cascade order: the second half of `index.css` | No, generated |
| `components/README.md` | The order blocks, the component rules, the files | Yes |
| `map-data.css` | The static map's data: Natural Earth masks, `--map-ratio`, each pin's place | No, generated by `scripts/concept/build_map.py` |
| `patterns/`, `docs/`, `examples/` | Empty for now | |

## What isn't here

- **The documentation layer:** the stand (`concept/stand.css`, `concept/specimens.css`), the showcase's stages (`ui/kit-doc.css`) and the first screen's comparisons (`concept/first-screen.css`). They describe the system; they aren't part of it.
- **The showcase (`ui/kit.html`), the shell (`ui/shell.html`) and the inventory (`ui/inventory.md`).** They stay in `ui/` and link the entry point like any screen.
- **`DESIGN.md`:** the design system documented from the code, at the repo root. Its frontmatter values and `.impeccable/design.json` are generated from `tokens/tokens.css` (`scripts/build_design_sidecar.py`).
